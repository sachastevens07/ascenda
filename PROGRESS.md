# Progress

Handoff notes for the next agent. Read `AGENTS.md` first (project brief + working rules), then this file.

## Done

1. **App shell**: Expo Router with a root `Stack` (`src/app/_layout.tsx`) and swipeable tabs, Today / Progress / Library / Profile (`src/app/(tabs)/_layout.tsx`), built on `expo-router/js-top-tabs` with `tabBarPosition="bottom"` and a custom floating pill tab bar (`src/components/PillTabBar.tsx`) whose highlight follows the swipe position.
2. **Auth**: Email + password via Supabase (`src/lib/supabase.ts`, `src/lib/auth.tsx`). `AuthProvider` tracks the session via `onAuthStateChange`, and the root layout uses `Stack.Protected` so signed-out users only see `src/app/sign-in.tsx` (sign in and create account on one screen). Profile shows the email and a Sign out button. The session persists in AsyncStorage.
3. **Exercise library**: 175 exercises in the Supabase `exercises` table, seeded from `supabase/exercises.sql`. The Library tab (`src/app/(tabs)/library.tsx`) loads all rows once and filters on the device: a search box (name, muscle and equipment words) plus Muscle and Equipment filter sheets (`src/components/FilterSheet.tsx`), with pull-to-refresh. The detail screen is `src/app/exercise/[id].tsx` (photo or placeholder, muscle tags, "Where to find it", 3 form cues, disclaimer). Types, labels and queries are in `src/lib/exercises.ts`.
4. **Onboarding quiz** (code complete, awaiting phone test): `profiles` table from `supabase/profiles.sql` (RLS: each user reads, inserts and updates only her own row; a trigger on `auth.users` creates an empty row on sign-up; existing accounts are backfilled). `src/lib/profile.tsx` holds the types, labels and a `ProfileProvider` / `useProfile()` that loads the signed-in user's profile and saves quiz answers. The quiz is `src/app/onboarding.tsx`: one question per screen (goal, experience, days per week, where you train, gym confidence 1–5), tapping an answer moves on, then a review screen (tap a row to change it, disclaimer, "Let's go"). The root layout sends signed-in users with no completed quiz to `onboarding` and only shows the tabs once it's saved. Profile tab shows "Your answers" with a "Change answers" button that reopens the quiz on its review screen.
5. **Programmes** (code complete, awaiting phone test): `supabase/programmes.sql` creates `programmes`, `programme_days` and `programme_exercises` (RLS: authenticated read-only) and seeds nine templates: Full body 2 days (`full-body-2`), Full body 3 days (`full-body-3`), Upper/lower 4 days (`upper-lower-4`), Lower-body focus 3/4/5/6 days (`lower-body-3` … `lower-body-6`), Five-day split (`split-5`: upper, lower, push, pull, legs) and Push/pull/legs 6 days (`ppl-6`). The 5- and 6-day plans are for experienced lifters only. Each exercise slot stores sets, a rep range and three exercises: `full_gym_exercise_id`, `dumbbells_exercise_id`, `home_exercise_id`. A trigger on `profiles` (`on_profile_answers_changed` → `programme_for_answers()`) sets `programme_id` whenever goal, experience or days change. `src/lib/programmes.ts` has the types and `fetchProgramme(id, equipment)`, which picks each slot's exercise for the user's equipment. The profile query also loads `programme:programmes(name, days_per_week)`. Profile tab shows a "Your programme" card with "View programme", which opens `src/app/programme.tsx` (days, exercises, sets × reps, tap an exercise for its detail screen, a note if she chose 1 day or more days than the plan has, disclaimer).
6. **Today screen** (code complete, awaiting phone test): `src/app/(tabs)/index.tsx` loads the user's programme (for her equipment) and shows a session card: programme name, "Your next session" / "Chosen session", "Day N of M", day name, then each exercise in order with sets × rep range and a weight suggestion (tap for the exercise detail screen). A tip explains how to find a starting weight. "Do a different day" opens a bottom sheet listing every day; "Back to your next session" resets it. The chosen day is screen state only (resets when the app restarts). Helpers in `src/lib/programmes.ts`: `getNextDay()` (always day 1 until sessions are logged), `WeightSuggestion` type, `getWeightSuggestion()` and `describeWeightSuggestion()`. No SQL changes.

## Decisions made (not in AGENTS.md)

- **Expo SDK 57**, not 58: Expo Go on the Play Store only supported SDK 57. Upgrade once Expo Go 58 ships. `react-dom` is pinned to match `react`.
- **Libraries added (approved by the user)**: `@expo/vector-icons` + `expo-font` (Ionicons tab and UI icons), `react-native-pager-view` + `react-native-tab-view` (swipeable tabs via Expo Router's `js-top-tabs`), `@supabase/supabase-js` + `@react-native-async-storage/async-storage`. No polyfill is needed (Expo provides `URL`).
- **Design**: background `#F7F4F0`, accent plum `#7A3E6B`, soft accent `#F2E6EE` (`src/constants/theme.ts`). No screen headers on the tabs; each screen shows its own big title. Large tap targets (at least 48–56px). Filters use bottom-sheet modals rather than horizontal chip rows, to avoid clashing with tab swipes.
- **Auth copy**: friendly error messages; "Nearly there! Check your inbox…" if sign-up returns no session.
- **Exercise data model**: `id` is a text slug (e.g. `goblet-squat`). Muscles: glutes, quads, hamstrings, adductors (labelled "Inner thighs"), calves, chest, back, shoulders, biceps, triceps, core. Equipment: barbell, dumbbell, machine, cable, kettlebell, band, bodyweight. The database enforces these lists and exactly 3 cues; keep the SQL constraints and `src/lib/exercises.ts` in step.
- **Photos**: public Storage bucket `exercise-media`. A trigger on `storage.objects` sets `exercises.media_url` to the file path when a file named `<exercise-id>.<ext>` is uploaded (case, spaces and underscores normalised) and clears it on delete. `media_url` may also be a full https URL. The app resolves it with `getMediaUrl()`. Re-running the SQL never overwrites `media_url`.
- **Disclaimer** ("General fitness guidance, not medical advice. Stop if anything hurts.") is shown on every exercise detail screen.
- In dev builds (`__DEV__`), the Library error state shows the real error message, and the photo placeholder shows the file name to upload.
- **Quiz values** stored in `profiles` (database constraints enforce them; keep `supabase/profiles.sql` and `src/lib/profile.tsx` in step): goal `strength` / `glutes_legs` / `general`; experience `new` / `some` / `confident`; `days_per_week` 1–6 (the user asked for a wider range than the brief's 2–4; 7 is left out so there's always a rest day); equipment `full_gym` / `dumbbells` / `home`; confidence 1–5. The quiz's "where you train" type is `EquipmentAccess`, separate from an exercise's `Equipment`.
- **"At home"** means bodyweight + resistance bands (confirmed by the user). The "dumbbells only" slots use dumbbell or bodyweight exercises only (no bands, as those users may not own any).
- **Onboarding is complete** when `profiles.onboarding_completed_at` is set (and all five answers are present). `profiles.programme_id` has a foreign key to `programmes` (added by `programmes.sql`, `on delete set null`).
- **Programme assignment rules** (agreed with the user; the SQL function `programme_for_answers` is the source of truth; first match wins): 1–2 days → Full body 2 (1 day: one session a week, alternating A and B); new to lifting + 5–6 days → a 3-day plan (Lower-body focus 3 for glutes and legs, otherwise Full body 3); glutes and legs → Lower-body focus with the chosen number of days (3–6); new to lifting or 3 days → Full body 3; 4 days → Upper/lower 4; 5 days → Five-day split; 6 days → Push/pull/legs. A new lifter choosing 4 days gets Full body 3 (or Lower-body focus 4 for glutes and legs). Gym confidence doesn't affect the choice yet. The programme screen explains when she gets fewer days than she chose.
- **Template names**: the brief's "Beginner full body" is shown as "Full body" because confident lifters who pick 3 days get it too; its description says it's beginner-friendly.
- **Equipment variants are explicit data** (user's choice) rather than automatic substitution. The swap button (Feature 9) is separate.
- Templates are rewritten on each run of `programmes.sql`: programme and day rows are upserted (future `sessions` will reference `programme_days.id`, so never rename or delete day ids), and all `programme_exercises` rows are deleted and re-inserted.
- **Today screen** (user's choices): it shows the next day in order, plus a "Do a different day" picker. With no history, there's no suggested number: weighted exercises say "Find your starting weight" (with a tip box), bodyweight ones say "Bodyweight", band ones "Choose a band that feels challenging". Once sets are logged, the suggestion should become her last weight (and Feature 8's progression). Today has no date logic: it always shows the next session, never "rest day" (no streak guilt). There's no Start button yet; it arrives with the logger.
- Supabase has no generated TypeScript types in this project, so embedded relations (e.g. `programme:programmes(...)`) are cast through `unknown` to the hand-written types.
- If the profile fails to load, the app shows a "We couldn't load your profile" screen with Try again and Sign out, rather than sending the user into the quiz. The first quiz question has a "Not you? Sign out" link.
